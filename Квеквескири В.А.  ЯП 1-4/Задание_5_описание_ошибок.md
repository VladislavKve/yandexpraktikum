# Задание 5. Описание найденных ошибок в JSON-запросе

## Эталон (из урока «Работа над проектом. Задание 5»)

Таблицы: **users**, **shops**, **tasks**, **task_assignments**, **specialists**, **contracts**, **task_status_history**, **recruitment_requests**.

**tasks:** id (PK), title, description, start_date, end_date, requirements, status, created_by, shop_id (FK → shops.id).

Трассировочная матрица: tasks.title, tasks.start_date, tasks.end_date, tasks.requirements, tasks.status.

---

## Найденные ошибки

### 1. Опечатка: `descripton` вместо `description`

**Где:** `tasks[0].descripton`

**Суть:** Опечатка в имени поля — пропущена буква «i». По эталону поле называется `description` (описание работ).

**Исправление:** `descripton` → `description`.

---

### 2. Неверное имя поля: `location_id` вместо `shop_id`

**Где:** `tasks[0].location_id`

**Суть:** По эталону ER таблица `shops` имеет первичный ключ `id`. Внешний ключ из `tasks` на магазин должен называться `shop_id`, а не `location_id`.

**Исправление:** Заменить `location_id` на `shop_id`.

---

### 3. Логическая ошибка: end_date раньше start_date

**Где:** `start_date: "2025-09-22"`, `end_date: "2025-09-20"`

**Суть:** Дата окончания (20 сентября) раньше даты начала (22 сентября). По бизнес-логике `end_date` должна быть не раньше `start_date`.

**Исправление:** Исправить порядок дат: `start_date: "2025-09-20"`, `end_date: "2025-09-22"`.

---

## Итог

Найдено и исправлено 3 ошибки (минимум по заданию):
1. `descripton` → `description` (опечатка)
2. `location_id` → `shop_id` (по эталону: tasks.shop_id FK → shops.id)
3. Даты: end_date должна быть ≥ start_date

---

## Примечание

В эталоне урока используются `id` и `title` (не `task_id` и `work_name`). Исходный JSON корректен по этим полям.
