# Чтение диаграмм прецедентов и типы связей
**Источник:** Яндекс Практикум | Спринт 5 | Тема 3 | Урок 3

## Типы связей в Use Case
1. **Ассоциация (Association)**: Обычная связь между актором и прецедентом.
2. **Включение (Include)**: Обязательное выполнение одного прецедента внутри другого (например, "Оформить заказ" включает "Авторизоваться").
3. **Расширение (Extend)**: Опциональное выполнение действия при определенных условиях (например, "Оформить заказ" расширяется "Написать комментарий курьеру").
4. **Обобщение (Generalization)**: Наследование свойств (например, актор "Администратор" наследует действия актора "Пользователь").

## Важные правила
- **Не путайте Include и Extend**: Если действие обязательно — это Include. Если действие выполняется "по желанию" или "иногда" — это Extend.
- **Читаемость**: Диаграмма должна быть понятна заказчику. Если вы неправильно укажете связь, заказчик может ожидать другой функционал.

## Пример из практики (Бронирование места в офисе)
- **Основной поток**: Выбор даты -> Выбор площадки -> Выбор места.
- **Опционально (Extend)**: Выбор оборудования (монитор, мышь).
- **Взаимодействие с внешними системами**: Система "Кадровик" предоставляет данные о сотрудниках (вторичный актор).
