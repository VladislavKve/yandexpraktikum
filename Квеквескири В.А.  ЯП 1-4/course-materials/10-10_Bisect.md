# Поиск и обнаружение ошибок (bisect)
**Спринт 10/13 | Тема 3/4: Продвинутая работа с коммитами | Урок 3/4**

## Команда git bisect

Назначение: найти коммит, в котором впервые появилась ошибка, методом бинарного поиска. Вместо перебора сотен коммитов — порядка log₂(N) проверок.

## Последовательность применения

1. **Открываем сеанс поиска:**
   ```bash
   git bisect start
   ```
   Git сообщает, что ожидает помечания плохих или хороших коммитов.

2. **Помечаем текущий коммит как «плохой»** (в нём ошибка присутствует):
   ```bash
   git bisect bad
   ```

3. **Указываем хеш хорошего коммита** (когда уверены, что всё работает):
   ```bash
   git bisect good <хеш_хорошего_коммита>
   ```

4. **Переключение:** Git переводит HEAD на промежуточный коммит (посередине между хорошим и плохим).

5. **Проверяем работоспособность:**
   - Ошибка сохраняется → `git bisect bad`
   - Ошибка исчезла → `git bisect good`
   Повторяем до тех пор, пока Git не найдёт первый «плохой» коммит.

6. **Завершение сеанса:**
   ```bash
   git bisect reset
   ```
   Возврат к исходной ветке.

## Запуск скриптов для проверки результата

`git bisect run <скрипт>` — автоматический поиск:
- **0** — успех (коммит помечается как good);
- **1** — ошибка (коммит помечается как bad).
- `git bisect visualize` — просмотр текущего состояния поиска (например, в gitk).

## Тесты

1. **Когда ошибка исчезла в проверяемом коммите** → `git bisect good`
2. **Какой алгоритм использует git bisect?** → Бинарный (двоичный) поиск

## Практическое задание

1. Создать Git-репозиторий и сделать 5+ коммитов.
2. `git bisect start`
3. `git bisect bad` — пометить текущий как плохой
4. `git bisect good <хеш_первого_коммита>` — пометить первый как хороший
5. Пошагово отмечать good/bad до нахождения первого проблемного коммита
6. Результат — вывод о найденном первом проблемном коммите
