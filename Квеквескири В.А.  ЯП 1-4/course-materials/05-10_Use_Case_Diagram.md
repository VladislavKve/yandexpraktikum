# Диаграмма прецедентов (Use Case Diagram)
**Источник:** Яндекс Практикум | Спринт 5 | Тема 3 | Урок 2

## Основные элементы
1. **Актор (Actor)**: Роль, взаимодействующая с системой.
   - *Первичный*: Инициирует действие (рисуется слева).
   - *Вторичный*: Помогает системе выполнить задачу (рисуется справа, например, внешняя API или БД).
2. **Вариант использования (Use Case)**: Описание функции системы (рисуется в овале).
3. **Граница системы (System Boundary)**: Прямоугольник, отделяющий систему от внешнего мира.
4. **Связи (Relationships)**: Линии между акторами и прецедентами.

## Как выделять акторов
- Кто предоставляет системе данные?
- Кто получает уведомления от системы?
- Кто помогает системе выполнить задачу?
*Важно*: Актором может быть не только человек, но и другая система или устройство.

## Рекомендации для проекта
- В Задании 4 (Sequence) ваши акторы должны совпадать с теми, что вы могли бы выделить для Use Case.
- Убедитесь, что вы разделяете "Пользователя" и "Систему". Система не может быть первичным актором для самой себя.
- Если в процессе участвует "Управляющий офиса" (как в вашем Sequence), он должен быть выделен как отдельный актор.
