# Алгоритм проектирования диаграммы последовательности

На основе примера «Сайт-агрегатор авиабилетов» из Яндекс Практикума.

## Шаг 1: Определение участников
Разделите всех участников на **акторов** (внешние) и **объекты** (внутренние/технические).
*   *Пример:* Клиент (Актор), Сайт (Объект), API Авиакомпании (Объект).

## Шаг 2: Описание взаимодействий (Таблица)
Для структурирования удобно использовать таблицу:
1.  Порядок вызова.
2.  Действие.
3.  Отправитель.
4.  Получатель.
5.  Тип взаимодействия (REST/SOAP).
6.  Метод (GET/POST/...).

## Шаг 3: Отрисовка базового сценария
Расположите участников слева направо в порядке их первого появления в процессе. Проведите линии жизни.

## Шаг 4: Добавление логики (Фреймы)
*   Используйте `alt` для успешных и неуспешных сценариев (например, оплата прошла / не прошла).
*   Используйте `loop` для повторяющихся действий.
*   Используйте `par` для параллельных запросов (например, поиск билетов в нескольких авиакомпаниях одновременно).

## Шаг 5: Детализация сообщений
Указывайте не только название действия, но и технические детали, если это необходимо (например, `POST /booking`, `200 OK`).
