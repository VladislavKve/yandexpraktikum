# Работа с удалёнными репозиториями
**Спринт 10/13 | Тема 2/4: Продвинутая работа с удалёнными репозиториями и тегами и псевдонимы | Урок 1/3**

Git — распределённая система: код хранится на удалённом сервере, члены команды работают с локальной копией.

## Удалённый репозиторий

### Зачем нужны удалённые репозитории
- **Совместная работа** — несколько разработчиков над одним проектом одновременно.
- **Резервное копирование** — защита от потери данных.
- **Управление версиями** — отслеживание изменений в больших командах.
- **Интеграция CI/CD** — автоматизация тестирования и развёртывания.
- **Обсуждения и код-ревью** — улучшение качества кода.

## Основные команды

### Клонирование (git clone)
`git clone [опции] <URL> [название папки]`
- `-b` / `--branch` — выбрать ветку при клонировании.
- `--depth <n>` — облегчённый клон, только последние n коммитов.
- `--single-branch` — только указанная ветка.
- `--recurse-submodules` — клонировать подмодули.
- `-o` / `--origin` — имя для remote (по умолчанию origin).

### Отправка изменений (git push)
`git push [опции] [remote] [ветка]`
- `-f` / `--force` — принудительно (осторожно: потеря работы других, нарушение истории, конфликты).
- `-u` / `--set-upstream` — связать локальную и удалённую ветки.
- `--dry-run` — показать без отправки.
- `--tags` — отправить теги.
- `--all` — отправить все ветки.

### Получение без обновления (git fetch)
Загружает изменения, не обновляя рабочую копию.
- `--all` — из всех удалённых веток.
- `--prune` — удалить ссылки на удалённые ветки.
- `--tags` — загрузить теги.
- `--dry-run`.

### Получение с обновлением (git pull)
fetch + merge.
- `--rebase` — rebase вместо merge.
- `--no-edit` — не открывать редактор для сообщения коммита.
- `--all` — из всех веток.

## Настройка удалённого репозитория (git remote)
- `git remote add <имя> <URL>` — добавить.
- `git remote rename <старое> <новое>` — переименовать.
- `git remote set-url <имя> <новый URL>` — изменить URL.
- `git remote` — просмотр.
- `git remote remove <имя>` — удалить.

## Работа с несколькими удалёнными репозиториями
**Когда нужны:** резервное копирование, подмодули, разные команды/платформы, dev/test/deploy, несколько версий проекта.
**Подходы:** понятные имена (origin, backup, staging), чёткое разделение задач, консистентность при синхронизации.
