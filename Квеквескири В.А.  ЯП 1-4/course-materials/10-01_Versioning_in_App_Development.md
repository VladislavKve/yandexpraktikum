# Версионирование в разработке приложений
**Спринт 10/13 | Тема 1/4: Система контроля версий Git и парадигмы разработки | Урок 1/4**

## Зачем нужен контроль версий
Разработчикам нужно было параллельно и независимо друг от друга работать над одной программой и иметь инструмент для версионирования.

## Subversion — решение проблемы
(До Git использовались централизованные системы, например Subversion.)

## Эволюция систем контроля версий. Git
- **Распределённое управление:** В Git любой разработчик мог работать со своей копией проекта так, будто это был основной репозиторий, а затем при необходимости синхронизировать изменения с остальными.
- **Быстрота:** Большинство операций в Git выполнялись локально. Разработчики получили возможность мгновенно переключаться между ветками, видеть историю коммитов, создавать и откатывать изменения без задержек.

## Основные термины: репозиторий, коммит, ветка
- **Репозиторий:**
  - локальный (local) — находится на компьютере разработчика;
  - удалённый (remote) — хранится на сервере или в облаке.
- **Коммит** содержит:
  - дата изменения;
  - автор изменения (как правило, электронная почта);
  - текстовый комментарий;
  - хеш-сумма.
- **Ветка** — параллельная линия разработки.

## Итоги
Версионирование необходимо для командной разработки: позволяет работать над одним проектом параллельно и отслеживать изменения.
