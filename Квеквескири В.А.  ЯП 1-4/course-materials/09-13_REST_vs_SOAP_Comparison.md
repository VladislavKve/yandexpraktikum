# Сравнение REST и SOAP API

## REST API (Representational State Transfer)
Архитектурный стиль, использующий протокол HTTP для передачи данных.
*   **Форматы данных:** JSON (самый популярный), XML, простой текст.
*   **Принципы:**
    1.  **Клиент-серверная архитектура:** Независимость клиента и сервера.
    2.  **Stateless (без состояния):** Каждый запрос содержит всю необходимую информацию.
    3.  **Унифицированный интерфейс:** Использование стандартных HTTP-методов (GET, POST, PUT, DELETE).
    4.  **Кеширование:** Возможность сохранения ответов для повышения скорости.
    5.  **Многоуровневая система:** Слои (прокси, шлюзы) работают независимо.

## Сравнение REST и SOAP

| Характеристика | REST | SOAP |
| :--- | :--- | :--- |
| **Протокол** | HTTP / HTTPS | HTTP, SMTP, FTP и др. |
| **Формат данных** | JSON, XML, Text | Только XML |
| **Сложность** | Проще в разработке | Сложнее, строгая спецификация |
| **Гибкость** | Высокая | Низкая (жесткая структура) |
| **Стандарт** | Архитектурный стиль | Протокол/Фреймворк |

## Ключевые отличия
*   REST ориентирован на **ресурсы** (существительные), а SOAP — на **действия/операции** (глаголы).
*   REST использует стандартные коды состояния HTTP (200, 404, 500), SOAP передает ошибки в элементе `soap:Fault`.
